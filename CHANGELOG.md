# Changelog

All notable changes to fennec-economy, the agent context-economy crate extracted
from fennec-core: head/tail elision, duplicate-result references, the character
budget, and the token-saving mods that front ends consume.

Version 1.0.0 is published as `v1.0.0`. Dates below are commit dates.

## [1.0.0] - 2026-11-24

Version 1.0.0 is the current release. Measured on the working tree: 31 passed,
0 failed (hub lane `economy`, `cargo test --offline`, suites 4, measured
2026-11-24): 6 golden checks in `tests/python_golden.rs` plus 25 token-saving-mod
checks in `tests/token_saving_mods.rs`. Counts are generated by the hub —
`python benchmarks/results.py` in the suite root writes
`benchmarks/artifacts/hub/RESULTS.json` — not hand-maintained here.

### Added
- The crate itself (`1a83cd1`, 2026-11-16), extracted from fennec-core into its
  own repo: edition 2024, `rust-version = 1.85`, with `src/lib.rs` carrying the
  compaction / elision / compact-stats logic, the path dependency on
  `fennec-pyjson` (`../fennec-core/src/fennec-pyjson`) for Python-compatible
  character counting, and four golden fixtures under `goldens/`
  (`compact-input.json`, `compact-payload.json`, `compact-stats.json`,
  `elide.jsonl`)
- `tests/token_saving_mods.rs` covering the mod behaviours, widened by four more
  cases in `d7d0ad0` (2026-11-17) — the file carried 23 at `1a83cd1` and 25 here

### Changed
- The version returned to the suite ladder: `02a0982` (2026-11-16) set
  `Cargo.toml` to `2.0.0` "to match latest tag", and `d7d0ad0` (2026-11-17)
  brought it back to `1.0.0`, where it stands; that 2.x ladder was retired and no
  2.x tag exists in this repo (`git tag --list` is empty, so there was never a tag
  for `02a0982` to match)
- Docs and comments aligned with the extracted crate's real paths — the Rust
  port is documented against fennec-core's `context.py`, behaviour unchanged
  (`e979635`, 2026-11-22)

### Fixed
- The elision dedup digest is computed over the raw tool-result text, not the
  compressed rendering (`d7d0ad0`, 2026-11-17): hashing the optimized text could
  collapse two different tool results that summarise to the same string into one
  "[identical to …]" label and silently drop the second. Matches
  `context.compact`; covered by `results_that_summarise_alike_stay_distinct` and
  `a_repeated_result_is_still_recognised_after_the_mod` in
  `tests/token_saving_mods.rs`
